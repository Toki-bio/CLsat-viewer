CLsat Locus Viewer — manual

What this is

A locus-resolved browser for the CLsat satellite arrays catalogued across six Darevskia genome assemblies (mix, arm, val, unp, unm, nai). Every array in the catalogue is a segmented MASTER locus — a contiguous CLsat-similar domain, split where the dominant subfamily changes along the array. The viewer shows the raw evidence behind each call, so any statement in the paper can be checked at the level of a single locus.

Quick workflow

  • 1. Select a locus. Click a row in the Locus Table (left), or click an array in the Scaffold Overview. You can also type an ID (e.g. L152) into Find locus and press Go.
  • 2. Zoom in. Mouse-wheel to zoom, drag to pan. Zoom until individual monomers resolve — monomer-level tools need the array to be readable, not the whole scaffold.
  • 3. Get FASTA. Fetches the locus sequence (via NCBI or the local server).
  • 4. Analyze Monomers. Splits the fetched sequence into individual monomers.
  • 5. Inspect below. Monomer list → monomer map → MSA → terminal-monomer trim.

Panels

  • Scaffold Overview — every locus on the selected scaffold. Bar height = bitscore.
  • Per-window Bitscores — the selected locus scanned against all four CLsat consensuses, one bar per scan window. This is why a locus got its call: a composite array shows the dominant colour switching part-way along, and a contested locus shows two colours running neck-and-neck.
  • Locus Table — filter by ID, assembly, family or flag; the Show and Subtype filters stay in sync with the overview.
  • Locus Ends & Flanks — the unique sequence flanking the array, its truncation status, and the cross-assembly flank matches that define positional orthology.

Monomer analysis

  • Monomer list — every monomer with its coordinates, length and % identity to the consensus.
  • Monomer map — the array drawn as arrows; arrow direction is monomer strand. Hover to highlight.
  • MSA — monomers stacked and aligned, with the genomic flanks attached, so substitutions that recur down the array (candidate higher-order structure) are visible as vertical stripes.

Terminal monomers vs reference

Shown below the monomer analysis. It asks a narrow question: does the array begin and end on a whole monomer, or is the first/last monomer only partial?

  • Pick the reference: sub-subfamily, subfamily, or this-locus consensus.
  • ref row = the reference consensus. Dim grey = positions this monomer does not cover (missing coverage — not extra bases).
  • mono row = the actual genomic monomer. Underlined = matches the reference; red background = mismatch.
  • trim5 / trim3 = how many reference bases are missing from the start / end. Both zero means the terminal monomer is complete under the current rotation convention.
  • Dim lowercase at the outer edge = 5 bp of real genomic flank outside the array. If the array runs into a contig edge there is no flank, and the header says (contig edge).

Caveat worth remembering: a tandem monomer has no intrinsic start. “Complete” and “partial” are relative to the chosen rotation convention, not a biological landmark.

Inspection lists

Two curated sets, opened from the buttons in the sidebar. In both, clicking any row opens that locus.

  • Orthologous loci — all 550 loci with at least one usable unique flank, scored by how many other assemblies they are positionally orthologous to (flank identity ≥80%, ≥200 bp; direct partners only). Presets run from conserved in all five other assemblies (74 loci) down to strictly private — both flanks unique yet no ortholog anywhere (22 loci). The partner chips are clickable: use them to jump straight to the same genomic position in another genome and compare what satellite sits there. Positional conservation does not imply conserved content — 42% of orthologous pairs carry a different CLsat subfamily at the two ends.
  • Problematic loci — the 27 loci flagged by arbitration. These are the edge cases: composite arrays, short residual segments, and near-tied family calls. Columns show the seed call and its bitscore, the strongest competitor and its bitscore, and the margin Δ between them.

Arbitration flags

FlagMeaning
UNIQUE_SEED_WITH_COMPETITORClean seed call; a competitor scores but does not threaten it.
UNIQUE_SEED_CONTRADICTIONThe rescan confidently favours a different family than the seed (Δ ≥ 20 bits). Only 2 loci — inspect these.
SEED_CONFLICT_RESOLVEDSeeds from more than one subfamily fell in the locus; resolved by bitscore.
SEED_CONFLICT_RESOLVED_AMBIGUOUSAs above, but the margin is small.
SEGMENT_RESOLVEDLocus split at a sustained subfamily transition; each segment called cleanly.
SEGMENT_RESOLVED_AMBIGUOUSSplit locus whose segment boundary or call is uncertain.

Tips

  • The per-window bitscore track is the ground truth — a table label can hide a locus whose signal switches half-way.
  • If Analyze Monomers looks wrong, check you fetched the FASTA first and that the locus is zoomed in.
  • Esc closes any panel. All tables can be searched with the box at the top.
